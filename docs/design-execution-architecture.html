02 · State Machine Anatomy

Why "1 Screen" Represents 10 Behavioral Decisions

A static visual mockup shows only the happy path. A production-ready design resolves the full behavioral state machine before frontend development begins:

1. Initial State
Default filter parameters, initial sort order, 38px grid metrics.
2. Batch Selection
Floating 32px discrete bar & cross-page selection persistence.
3. Empty State
Zero search results guidance & actionable recovery triggers.
4. Error / Timeout
API 500 exceptions, timeout alerts & retry mechanisms.
5. Loading Skeleton
38px cell skeleton layout preventing layout shift (CLS).
6. Validation & Dirty
Dirty state tracking, unsaved changes alert, inline feedback.
7. Extreme Data Bounds
100-character titles, 10k table rows & ellipsis handling.
8. 100vh Viewport
Zero page scroll on 1080p monitors; internal table scroll.
9. Permission Bounds
Role-gated action buttons (disabled vs tooltip vs hidden).
10. Audit Trail & Lock
MASAK/SPK irreversible confirmation modal & tabular amounts.
03 · Estimation & Delivery Taxonomy

The Objective Measurement Model: What Are We Estimating?

Design duration is not arbitrary. It directly reflects the architectural depth and reliability contract required by engineering:

Deliverable Tier Scope & Decision Depth Handed-Off Output Typical Effort
Level 1: Rough Visual Concept Exploratory draft, single happy path, no error states, layout wireframe. Discussion Mockup Hours
Level 2: Refined Static Screen Mapped to floorplan, realistic dummy data, standardized form fields. Visual Approval Artifact ~0.5 – 1 Day
Level 3: Production-Ready Screen 10 behavioral states, edge-case bounds, AntD 6 tokens, zero-override contract. Development-Ready Spec 1 – 2+ Days
Level 4: Complex Workflow / Module Multi-step wizard, interactive canvas editor, asynchronous state machine. Modular Subsystem Several Days
"The exact time varies by complexity, but this is the objective distinction I'm making. A 1-day estimate represents a Level 3 production contract."
04 · The Operational Proposal

Proposed Working Protocol: Explicit Estimation Model

Moving forward, let us eliminate subjective time debates by establishing an objective estimation agreement between Product, Design, and Engineering:

1. Explicit Intake Categorization

For each incoming requirement, Product Owners and Engineering specify the deliverable tier up front:

  • If the squad only needs visual exploration for an ideation meeting: Level 1 (Hours).
  • If the squad demands a production-ready screen with zero downstream rework: Level 3 (1–2 Days).
2. Downstream Rework Prevention

Any screen delivered under a Level 3 estimate provides an infrastructure guarantee:

  • Engineers build the screen directly using Ant Design primitives in under 2.5 hours (-82% build time).
  • Zero styling overrides (`!important`), zero sprint-interruption questions, zero missing edge-case QA bugs.
