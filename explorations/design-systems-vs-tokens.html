Design Systems vs. Design Tokens: Architecture Over Aesthetics

By Murat Çetin · Published Dec 2024 · 4 min read

In many product organizations, there is widespread confusion between a Design System and a Figma UI Kit. Teams spend months drawing beautiful component stickers in Figma, only to watch development grind to a halt because none of the visual rules map cleanly into production code.

“A design system is not a visual library. A design system is a compiler pipeline that transforms design decisions into immutable, code-backed contracts.”

1. The UI Kit Illusion

A Figma UI Kit is a drawing tool for designers. It allows you to drag and drop buttons, inputs, and modals onto a digital canvas. But a drawing contains zero semantic constraints. It cannot prevent a developer from writing raw hex values, guessing padding scales, or overriding component cascades with fragile CSS.

When design tokens are treated as decorative color styles rather than data architecture, design drift begins on day one.

2. Design Tokens as the Source of Truth

In a mature enterprise architecture, tokens are formatted in the Design Tokens Community Group (DTCG) specification. The single source of truth is a pure JSON schema (e.g. core.json) that lives directly inside the code repository:

// packages/tokens/core.json
{
  "color": {
    "brand": {
      "primary": { "value": "#5D2BC7", "type": "color" }
    }
  },
  "spacing": {
    "base": { "value": "8px", "type": "dimension" }
  }
}

Using a build tool like Style Dictionary, this single JSON definition automatically compiles into multiple targets:

  • CSS Variables (:root { --color-brand-primary: #5D2BC7; })
  • Ant Design v5 Theme Tokens (agitoTheme.ts)
  • TypeScript Constant Types and Linting Rules

3. The Zero-Override Discipline

When the token pipeline is strictly connected to the component engine, custom CSS overrides become illegal:

  • No raw hex colors outside core.json.
  • No !important declarations anywhere in the repository.
  • No arbitrary spacing outside the 8px grid.

By shifting the focus from drawing pixels to architecting token pipelines, the organization achieves true DesignOps scalability: changing a brand token at the root propagates across 14+ enterprise products in seconds without a single line of manual refactoring.
