Agito InsurTech Modernization: Governing 14+ Enterprise Products with an Ant Design v5 Control System

How a sole Design Systems Architect dismantled a 5-year cycle of outsourced agency failures in a 250-engineer insurtech company—establishing a code-enforced Control System to deliver a 68-screen core foundation and absorb a multi-wave enterprise roadmap.

Act I / Context & Friction

The 3-Agency Inheritance & The Reality Wall

Agito is Turkey’s premier insurtech software vendor, powering the core transactional infrastructure for 35% of the national life, pension, and non-life insurance industry. When I joined as the company’s first and sole Lead Design Systems Architect, the organization had 250 employees—almost exclusively backend database developers, actuarial mathematicians, and corporate account managers—and zero centralized design infrastructure.

The executive mandate was immense: Modernize 14+ monolithic products (Policy Administration, Claims, Tahsilat & Collections, Workpool Queues, Global Parameter Definitions, and Document Generation) to compete against modern global platforms.

However, beneath the surface lay a five-year trail of expensive wreckage: Agito had hired three consecutive external design agencies, and all three engagements had collapsed completely.

The Agency Failure Diagnosis

"External design agencies operated as pure order-takers. They drew subjective, colorful Dribbble-style mockups for isolated Product Owner sprint requests. Because they lacked actuarial domain knowledge and frontend constraints, their deliverables broke down the moment engineering attempted to write reusable production code. Thousands of lines of fragile custom CSS piled up, creating insurmountable technical debt."

Act II / Cultural Resistance & Governance

The Inverted Waterfall Mandate & The UX Readiness Gate

During my first 90 days, organizational friction erupted. Leadership, accustomed to legacy agency dynamics, demanded an inverted waterfall: "Design the buttons, menus, and visual component library first so the Board can approve them, then we will decide the business logic."

Meanwhile, four separate Product Owners were running weekly sprints, submitting ad-hoc screen requests without problem statements or validated actor journeys.

I pushed back immediately. Drawing components in a vacuum is the fastest route to design system death. To stop the incoming chaos and establish architectural governance, I instituted the UX Readiness Gate.

GATE 1: USER ACTOR & PROBLEM BOUND
Who is operating this screen (Actuary, Collector, Claims Handler)? What specific friction or error is being solved?
GATE 2: END-TO-END FLOW BLUEPRINT
Current vs. target task journey mapped across module boundaries before opening Figma.
GATE 3: ACTUARIAL BUSINESS INVARIANTS
Explicit boundary rules: debt distribution algorithms, refund restrictions, and immutable regulatory constraints.
The Mandatory 3-Tier UX Readiness Gate Enforced Across All Product Squads

If a feature request lacked these three invariants, it was rejected at the gate. This single governance mechanism eliminated 70% of redundant screen churn before a single pixel was drawn.

Act III / The Turning Point

Month 7 Inflection Point: Test Automation Collapse & The Turing Point

The defining crisis arrived in Month 7. When the engineering organization attempted to write Cypress and Selenium automated test suites against screens implemented from legacy agency mockups, the frontend code collapsed.

Because the agency's static drawings had forced developers to write bespoke CSS and arbitrary nested DOM wrappers for every single screen, automated selectors broke on every minor build. Sprint delivery ground to a complete standstill.

I convened an executive session with the CTO, Engineering Directors, and Product Leadership. On a single slide, I presented the Side-by-Side Turing Audit:

❌ Outsourced Agency Drawings
  • Arbitrary, non-standard layout geometries
  • Nested conditional modals breaking state machines
  • Requires thousands of lines of bespoke CSS overrides
  • Broke QA test automation; zero predictable DOM selectors
✓ Ant Design v5 Control Architecture
  • 4 Universal Floorplans (100vh Viewport Fitting)
  • Single-screen modular tables & 2-row grid drawers
  • Zero custom CSS overrides (`agitoTheme` token compiler)
  • Deterministic DOM structure: 100% QA test automation passes

The proof was irrefutable. Engineering could not automate tests against drawings, but they could automate flawlessly against deterministic Ant Design v5 floorplans. Executive leadership halted all external agency contracts permanently and committed 100% of engineering resources to my Control Architecture.

Act IV / Platform Topology & Governance

The Multi-Wave Modernization Program & Component Topology

Agito’s transformation was not an isolated redesign of one or two features; it was a multi-wave platform modernization spanning 14+ core insurance products.

To prove that the Control System could govern this massive ecosystem, we established the Initial Wave 1 Baseline Inventory (68 Core Production Screens):

Modernization Scope Total Screens Completed (Done) In Progress / To-Do Architectural Role
Platform Core Infrastructure 36 Screens 17 Done 19 To-Do / Review Banks, Currencies, Parameters, Value Lists, System Messages.
Core Insurance Products 32 Screens 23 Done 9 To-Do Policy Admin, Claims, Collections, Workpool, Document Engine.
Wave 1 Foundation Total 68 Screens 40 Done (59%) 28 In Pipeline Foundation to absorb hundreds of upcoming Wave 2+ screens.

Within this 68-screen foundation, we established strict Component Topology & Modality Standards to govern how every single form, parameter, and transaction behaves:

Interaction Surface Structural Boundary Rule Production Target & Purpose
Modal (Dialog) Strictly restricted to 1–4 inputs; single atomic action. Quick approvals, state changes, status confirmations. No nested wizards.
Drawer (2-Row Grid) High-density multi-field parameters (5–12 inputs). Bank/branch definitions, currency rates, payment types without losing ledger context.
Standard Drawer Deep sequential record configuration. Holiday calendars, system message matrices, complex parameter trees.
Subpage / Detail View Multi-tab analytical entity inspection. Policy files, claims dossiers, full customer 360 dossiers.
Architectural Rule: Eliminating Modality Anti-Patterns

"A modal dialog is for single-intent confirmation. If an operation requires conditional branching or multi-field data entry, nesting it inside a modal creates severe cognitive friction and DOM validation errors. By replacing modals with 2-Row Grid Drawers and Subpages, we standardized interaction across all 68 initial screens and established an immutable pattern for hundreds of upcoming roadmap modules."

Act V / Scale & Solo Architect Leverage

Industrial Architecture & Solo Design Leverage

How does a single Lead Design Systems Architect govern 14+ products, deliver an initial 68-screen foundation, and prepare an enterprise for hundreds of upcoming screens without an agency army?

Through three immutable architectural layers:

1. The 4 Universal Floorplans (100vh Viewport Fitting)

I eliminated ad-hoc page layout debates across the company by proving that 100% of insurance enterprise workflows map cleanly into exactly 4 standardized floorplans, strictly optimized for 1920x1080 enterprise workstations with zero page-level vertical scroll:

[ TopBar: Global App Identity + Search + Profile ]
[ KPI Band: 4 Operational Metrics (Claims SLA, Open Collections, Active Policies) ]
[ Main Body: Workpool Task Queue (Left 60%) | Activity & Notification Stream (Right 40%) ]

Overview Floorplan: Daily operational hub for insurance handlers. Zero page bounce; internal queue scrolls independently.

[ Filter Bar: Multi-field Search + Date Pickers + Status Filters + Action Trigger Buttons ]
[ Data Table: 10-18 Columns, Frozen Action Column, Row Selection, Status Badges ]
[ Sticky Pagination Bar: Record Counters & Page Switcher ]

List Floorplan: The enterprise workhorse powering Policy Lists, Claims Ledgers, and Global System Parameters.

[ Object Header: Entity Title, Master Key, Status Tag, Primary Lifecycle Actions ]
[ Tab Navigation: General Terms | Financial Ledger | Endorsements | Audit Trail ]
[ High-Density Form Cards: 2-4 Column Grid with Floating Labels ]

Object Floorplan: Deep single-record inspection for Underwriting, Endorsements, and Customer 360 views.

[ Left Master Queue (35%): Searchable Entity Records with Visual Badges ]
[ Right Detail Inspector (65%): Live Actuarial Calculation & Edit Canvas ]

Analytical Split Floorplan: Designed for rapid claims reconciliation and real-time actuarial adjustments.

2. The DTCG Token Pipeline & Zero-Override Discipline

The single source of truth for all visual decisions is a pure JSON schema (`core.json`) governed by Design Tokens Community Group (DTCG) standards. Using Style Dictionary, tokens compile automatically into Ant Design v5 (`agitoTheme`):

  • Hard Denial Rules: Zero raw hex outside `core.json`, zero `!important`, zero gradients, and flat surfaces only.
  • Zero Custom CSS: Changing a brand or density token in `core.json` instantly re-themes all 14 enterprise products without breaking production code.

3. AI Subagent Compilation Pipeline

To eliminate the manual Figma bottleneck when multiple Product Owners demanded simultaneous delivery, I engineered an AI Subagent Compilation Pipeline.

By feeding actuarial rule sheets and standardized floorplan topologies directly to autonomous AI subagents, we compiled code-ready Ant Design v5 specifications in record time—delivering 8 full platform screens in initial sprints with zero manual handoff friction.

The Transformation Outcome

"By replacing five years of outsourced agency failures with an Ant Design v5 Control Architecture, Agito eliminated 100% of custom CSS drift, established an automated testable foundation across 68 core screens, and equipped a single Design Systems Architect to govern 14+ enterprise products across Turkey's regulated financial sector."
