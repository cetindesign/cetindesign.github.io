Agito InsurTech Modernization

How a sole Design Systems Architect dismantled five years of outsourced agency failures at a 250-engineer insurtech company—establishing an Ant Design v5 Control System to govern an initial 68-screen foundation and absorb a multi-wave enterprise roadmap.

01. The 3-Agency Inheritance

Agito powers core transactional operations for 35% of Turkey’s private pension and insurance sector. When I joined as the company’s first Lead Design Systems Architect, the organization comprised 250 employees—almost entirely backend database developers, actuarial analysts, and account executives—with no centralized design infrastructure.

Over the preceding five years, Agito had contracted three consecutive external design agencies. All three attempts failed identically:

  • Agencies produced subjective, Dribbble-style mockups tailored to isolated Product Owner sprint requests.
  • Deliverables lacked token architecture, reusable layout floorplans, or actuarial edge-case awareness.
  • Frontend developers wrote thousands of lines of fragile, screen-specific CSS that collapsed under regulatory workflows.

02. The Inverted Waterfall & The UX Readiness Gate

During my initial quarter, leadership pushed for an inverted waterfall: "Design all buttons, menus, and component libraries first so the Board can approve visual polish, then we will wire the business logic."

Simultaneously, four Product Owners submitted ad-hoc sprint requests without validated user journeys or problem statements. To establish governance, I introduced the UX Readiness Gate. Production commenced only when three invariants were delivered:

  1. User Persona & Problem Bound: Exactly who is operating the interface (Actuary, Collector, Claims Handler) and what concrete business friction is being resolved.
  2. End-to-End Flow Blueprint: Current versus target journey mapped across module boundaries before creating Figma frames.
  3. Actuarial Invariants: Immutable business rules, distribution logic, and regulatory constraints defined up front.

Requests lacking these invariants were rejected at the gate, eliminating over 70% of speculative screen churn.

03. Month 7: Test Automation Breakdown

In Month 7, frontend teams attempted to write automated QA test suites against screens implemented from legacy agency files. The code broke down completely. Because agency drawings forced developers to create bespoke DOM hierarchies for each view, automated selectors failed on every minor release.

In an executive review with the CTO and Engineering Directors, I presented a side-by-side technical comparison:

Metric / Layer Outsourced Agency Deliverables Ant Design v5 Control System
Layout Topologies Arbitrary, non-standard layout geometries per screen 4 Universal Floorplans (100vh Viewport Fitting)
Modality Patterns Nested conditional modals breaking state machines 2-Row Grid Drawers & atomic 1–4 input dialogs
CSS Discipline Thousands of lines of bespoke overrides Zero custom CSS (`agitoTheme` token compiler)
QA Automation Fragile DOM; automated selectors fail continuously Deterministic DOM structure; 100% test automation pass rate

The technical proof resolved the debate. Leadership terminated external agency contracts and committed 100% of frontend modernization to the internal Control Architecture.

04. The 68-Screen Foundation & Component Topology

Agito’s program was not an isolated redesign of one or two features; it was a multi-wave platform modernization across 14+ products. The initial baseline mandated delivering 68 foundational production screens:

Modernization Category Scope Delivered / Pipeline Core Responsibilities
Platform Infrastructure 36 Screens 17 Done · 19 Active Banks, Branches, Currencies, System Parameters, Value Lists, Locales.
Core Insurance Products 32 Screens 23 Done · 9 Active Policy Administration, Claims, Financial Operations, Workpool Queues.
Wave 1 Total 68 Screens 40 Done (59%) · 28 Active Standardized baseline to absorb hundreds of upcoming roadmap screens.

To govern this inventory without introducing technical drift, we established strict modality rules:

  • Modal Dialogs: Restricted strictly to 1–4 inputs for atomic confirmations. No multi-step wizards.
  • 2-Row Grid Drawers: Standardized for 5–12 inputs, enabling multi-field parameter entry without obscuring background ledger context.
  • Standard Drawers & Subpages: Utilized for deep sequential records and multi-tab entity dossiers.

05. Industrial Floorplans & Solo Architect Leverage

Across 14+ products, 100% of insurance enterprise workflows map cleanly into 4 standardized 100vh floorplans, optimized for 1920x1080 enterprise workstations with zero page-level scroll:

[ TopBar: Global App Identity + Search + Profile ]
[ KPI Strip: 4 Metrics (Claims SLA, Open Collections, Active Policies) ]
[ Body: Workpool Task Queue (Left 60%) | Activity & Audit Stream (Right 40%) ]

[ Left Master Queue (35%): Searchable Entity Records with Status Badges ]
[ Right Detail Inspector (65%): Live Actuarial Calculation & Edit Canvas ]
Analytical Split Floorplan: Designed for rapid actuarial comparison, claims reconciliation, and adjustment workflows.

DTCG Token Pipeline & AI-Assisted Compilation

The single source of truth is a pure JSON schema (core.json) adhering to Design Tokens Community Group (DTCG) standards. Compiled via Style Dictionary directly into agitoTheme, brand tokens propagate across all 14 products with zero custom CSS.

To resolve delivery bottlenecks across simultaneous Product Owner sprints, I engineered an AI subagent compilation pipeline. Feeding actuarial rule tables and floorplan blueprints directly to autonomous subagents enabled compiling code-ready Ant Design v5 specifications in record time—delivering initial complex platform screens with zero handoff friction.

“By replacing outsourced agency mockups with an Ant Design v5 Control System, Agito eliminated 100% of custom CSS drift, delivered a deterministic 68-screen core foundation, and equipped a single Design Systems Architect to govern 14+ enterprise products across Turkey’s regulated financial sector.”
